System Design

Architecture Overview

Five-layer architecture from the Rust backend to the React UI, with each layer handling a specific responsibility.

50 Rust Commands

From git_status to git_bisect_start — every command parses git output into strongly-typed structs with proper error handling.

65 TypeScript Bridges

Direct 1:1 mapping through Tauri's invoke(). Every Rust command is wrapped with full TypeScript types and nullable defaults.

Web Worker Offloading

CPU-heavy operations run in a background thread with an LRU cache (100 entries max) and per-type TTLs from 0ms to 30s.

How It Works

Operation Data Flow

Follow a git operation — like staging a hunk — through all five layers of the architecture.

1
User Clicks "Stage Hunk"
The diff view renders a "Stage" button on each hunk block. Clicking it calls handleStageHunk(index) in GitDiffView.tsx.
GitDiffView.tsx → store.stageHunk(filePath, hunkIndex)
2
Zustand Store Dispatches
stageHunk action sets loading state, gets repoRoot, clears hunk cache, and calls the Tauri bridge.
gitStore.ts → gitStageHunkCmd(root, filePath, hunkIndex)
3
Tauri Bridge Invokes Rust
invoke('git_stage_hunk', { root, filePath, hunkIndex }) crosses the JS→Rust boundary. Serialized as JSON via serde.
git.ts → invoke("git_stage_hunk")
4
Rust Executes Git
Runs git diff --no-color --unified=3, parses the specific hunk, builds a patch, and applies it with git apply --cached. Returns Result<(), String>.
git.rs → Command::new("git").args([...]).output()
5
Response Flows Back
Result propagates back through Tauri → TypeScript → Store → Component. Store calls refreshStatus() and clears diffHunkCache. Component re-focuses.
containerRef.current?.focus() — keyboard flow maintained
